# 2026.326.1616 — feat(box)!: aur is a routed builder in kde-vnc, and its imports move to the releases that agree

## Summary

`aur` stops being a box `build:` format and becomes what it always was — a routed builder — for this repo's image, and the two namespaces it imports move to the releases that agree with that (opencharly/sdk#608, the unified builder mechanism).

- **`kde-vnc` drops `aur` from its `build:` list.** `build:` names OS package formats only; an AUR package reaches an image because the candy that declares it (`distro.<tag>.aur`) is composed and the build routes the `aur` builder to `arch.arch-builder`, which this box already declares. The old form was the opt-in whose absence silently dropped the declaration — the defect that left `kdotool` out of an image (opencharly/layer-kde-shell#7).
- **`arch:` `v2026.325.1112` → `v2026.326.1455`** — the distro-arch release where `aur` is a routed builder (distro-arch#77). Its `arch-test` carries `build: [pac]`, and the builder map this import exists to reach is unchanged.
- **`podcdi:` `v2026.325.1329` → `v2026.326.1530`** — the pod-cdi release built on that same distro-arch generation (pod-cdi#13), so the direct and the transitive namespace agree.
- The comment block above the pins now names the releases it points at and why, so the justification does not drift from the values.
