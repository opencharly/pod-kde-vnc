# 2026.330.1628 — fix(session): give the image a Plasma session default, and name it where it matters

## Summary

The pod's IMAGE default for the session environment now describes Plasma, and the two bed steps
that need a specific session say so explicitly — the difference between the two matters, and it is
the measurement this change carries.

- **`kde-vnc-session` sets the image's session pair**: `WAYLAND_DISPLAY=wayland-kde` and
  `KDE_SESSION_VERSION=6`. Before, the pod inherited pod-sway's candy env, so the ambient display
  was `wayland-0` — the compositor BEHIND the fullscreen KWin window, where a client renders itself
  invisible in the VNC stream. Safe by construction: sway's and wayvnc's own `service:` entries set
  `WAYLAND_DISPLAY=wayland-0` themselves (a service must not depend on ambient drift, and both must
  reach the compositor socket), and `kde-nested` uses the `KDE_NESTED_*` knobs.
- **A check step still names its session, and that is the correction this change made to its own
  first draft.** Measured on the live bed: a check step's in-container command environment carries
  the OPERATOR's environment — the runner's own `WAYLAND_DISPLAY` reached the container, so
  `setsid konsole` inherited a socket that does not exist inside the pod and never opened a window
  (the Konsole step failed, and the KWin-focus check then read Chrome's window instead). The bed
  therefore keeps its explicit `WAYLAND_DISPLAY=wayland-kde` on the Konsole launch and
  `KDE_SESSION_VERSION=6` on the `kdotool` call: not a workaround, but the statement of which
  session the step targets.
- **The rule is documented where it is read**: the skill's ambient-session section and this repo's
  rulebook state the image default, the forwarding caveat, and that the image's values are
  checkable host-side (`podman image inspect`) rather than from an in-container `printenv`
  (`charly check image` forwards the host env too — measured).

### Spike

Two candidate shapes for "where the image's session default is declared", both tried on the real
generator:

```
# (a) the session value on the CANDY (chosen) — the generated Containerfile, the candy's block AFTER
#     pod-sway's, so the later ENV wins; exit 0
$ charly -C pod-kde-vnc box generate kde-vnc
122:ENV KDE_SESSION_VERSION="6"
127:ENV WAYLAND_DISPLAY="wayland-kde"

# (b) the session value on the IMAGE's own env: — tried and REJECTED: it emits no ENV line at all,
#     so the image cannot be the declaration point; exit 0, and the only WAYLAND_DISPLAY left is
#     pod-sway's
$ grep -n '^ENV WAYLAND_DISPLAY' .build/kde-vnc/Containerfile
126:ENV WAYLAND_DISPLAY="wayland-0"
```

Winner: (a). A third reading — "leave the ambient value alone and let each service set it" — is not a
candidate for this change: the services already set their own value on the unchanged tree, and the
defect is every OTHER client, which is exactly what `bed-container-session-env` now measures.
