# 2026.326.2247 — feat(box)!: compose pod-kde-nested for the nested session, and delete this pod's own launcher

## Summary

The nested Plasma session stops being this pod's own code. `kde-vnc-session` (68 lines) and its `service:` block — the `mkdir`, the `copy: kde-vnc-session`, and the build-time `setcap -r` strip — are deleted; the service is `kde-nested`, owned by opencharly/pod-kde-nested, which this pod now composes at its first release, **`v2026.326.2127`** (not `:main`: a moving ref is not a pin).

- **What stays here** are this pod's choices, passed to the candy as its inputs: host display `wayland-0` (sway), nested socket `wayland-kde`, runtime dir `/tmp`, `session` bus — the pod-kde-vnc row of the candy's consumer matrix.
- **ONE knob sizes both, by construction.** The candy keeps `env_accept: RESOLUTION` for sway's output and passes **no** `KDE_NESTED_RESOLUTION`: the composed session documents an empty value as "take the size the output gives", so a consumer who sets `RESOLUTION: 2560x1440` gets a 2560x1440 sway output *and* a KWin window that fills it. A second literal here would let the two diverge with no consumer-facing way to fix it — so it is not there.
- **The bed's services check names `kde-nested`** beside sway and wayvnc, which is what "the composed service is the one running" means.
- **The skill and rulebook follow the code**: they say the session comes from the composed candy and that pod-kde-nested owns the launcher; the duplicated explanation of KWin nesting (now the candy's job) is gone, and the skill states that this pod sets **no** `KDE_NESTED_RESOLUTION` — the geometry paragraph that documented the removed knob and a hardcoded `--width 1920 --height 1080` was corrected in the same change (`eb1a8f4`), by a claim-keyed sweep for the literal across the tree.
